## Data sources

The model was trained on a synthetic dataset generated to replicate the statistical properties of internal historical credit decision data. No real personal data was used in the training set for this mock deployment. The dataset contains 1,000 records with the following fields:

| Field | Type | Source |
|-------|------|--------|
| `income` | Continuous | Synthetic — log-normal distribution calibrated to UK income deciles |
| `credit_score` | Continuous | Synthetic — normal distribution N(650, 80) |
| `loan_amount` | Continuous | Synthetic — correlated with income |
| `age` | Continuous | Synthetic — uniform(22, 70) |
| `gender` | Categorical | Synthetic — 50/50 split (for bias evaluation purposes only) |
| `label` | Binary | Deterministic rule: approved if `credit_score > 600 and income > 25000` |

The dataset was generated by the ML team using `seed/data_generator.py` with a fixed random seed (42) to ensure reproducibility.

---

## Collection method

This is a synthetic dataset. No data was collected from data subjects. The generation procedure was:

1. Sample demographic and financial features from calibrated distributions.
2. Apply the deterministic labelling rule to generate ground-truth outcomes.
3. Inject a small amount of gender-correlated feature noise to create a realistic fairness evaluation scenario.
4. Version and store the dataset at `seed/data/credit-scoring-v3.csv` (SHA-256 checksum pinned in `seed/checksums.yaml`).

The labelling rule is fully deterministic and human-defined — no human labellers were involved.

## Known biases

| Bias | Description | Severity | Mitigation |
|------|-------------|----------|------------|
| Gender correlation | The generation script introduces a small positive correlation between gender and income (~0.15 Pearson r) to simulate real-world income gap patterns. This can cause the model to learn a spurious gender-to-income-to-approval path. | Medium | Fairness tests FAIR-001 (disparate impact) and FAIR-004 (FPR parity) are run on every evaluation to detect and flag this effect. |
| Age range truncation | Ages below 22 are excluded, reflecting legal minimum for credit in the UK. This means the model has no training signal for young adults. | Low | Documented in the model card. Any deployment to products serving 18-21 year olds requires a separate evaluation. |
| Label determinism | The labelling rule is a simplified proxy for real credit decisions and does not capture the full complexity of underwriting. | Medium | The dataset is for framework testing only. Production deployment requires retraining on real labelled data with an appropriate approval process. |
